# Code Review Basics
Code review is the process of examining proposed changes before they are merged into a project.

For many contributors, the review stage is where most of the learning happens. Reviewers may ask questions, suggest improvements, request changes, or approve the condition. This is a normal part of the contribution process and should be viewed as a collaboration rather than an evaluation.

## Receiving Feedback
Review comments are usually directed at the contribution, not the contributor.

When receiving feedback:
- Read comments carefully
- Ask for clarification when needed
- Make requested changes when appropriate
- Explain your reasoning if you disagree

Most reviews become productive discussion when contributors communicate respectfully and professionally.

## Updating Your Pull Request
It is common to update a pull request several times during review. Reviewers may identify edge cases, documentation gaps, testing concerns, or opportunities to simplify the implementation.

To update your pull request:
1. Make the requested changes in your local files
2. Commit the updates
3. Push the new commits to the same branch

The pull request will automatically update to include the new commits.

Requested changes are not a sign of failure. Even experienced contributors regularly revise their work before it is merged.
